## 二、请求层协议（必须完全一致）

### 2.1 基础地址

| 常量 | 值 |
|---|---|
| `ApiHost` | `https://apinew.hfeyusheng.top` |
| `BaseUrl` | `/api`（生产构建下与 ApiHost 合并） |
| 完整前缀 | `https://apinew.hfeyusheng.top/api` |
| 插件前缀 | `https://apinew.hfeyusheng.top/addons`（`needBaseUrl:false` 的接口走这里） |
| TokenKey | `token` |

### 2.2 签名算法（关键）

```js
sign = md5(完整URL + 大写METHOD)
```

- 完整 URL = `ApiHost + BaseUrl + path`（含 query），**不含** base64 之外的任何部分
- 请求头 `sign: <md5>`
- 示例：`md5("https://apinew.hfeyusheng.top/api/user/login" + "POST")` = `62f65f4b8887fbae79b8a3724615d619`

### 2.3 公共请求头

| Header | 值 |
|---|---|
| `Content-Type` | `application/json` |
| `sign` | md5(url + method) |
| `token` | 登录后 token（未登录为空） |
| `version` | App 版本号，取 `getConfig` 的 `app_version` = `1.1.2` |
| `Cache-Control` | `no-cache` |
| `Origin` / `Referer` | 站点域名 |

### 2.4 统一响应包

```json
{ "code": 1, "msg": "个人信息", "time": "1792403294", "data": {} }
```

| 字段 | 说明 |
|---|---|
| `code` | `1` = 成功；`0` = 业务失败；`-1` = 未登录 |
| `msg` | 提示文案，前端直接 toast |
| `time` | 服务端时间戳（字符串） |
| `data` | 业务数据 |

### 2.5 登录

```
POST /api/user/login
{ "account": "手机号", "password": "密码" }
→ data.token, data.expiretime, data.expires_in(2592000), data.userinfo
```
另一路径 `POST /api/user/LoginForMobile`（验证码登录，参数 `{mobile, captcha}`）。

## 四点六、原站 runtime 故障记录与反编译方法论

### 4.6.1 原站整站白屏（2026-10-19）

**现象**：首页起全站白屏，控制台报
`TypeError: Cannot read properties of undefined (reading 'split')`

**定位**：`chunk-vendors.09c31d96.js` 中 `getSystemInfoSync` 调用链抛出，发生在 uni-app runtime 初始化阶段，页面渲染前。

**已排除的可能**（共 8 次尝试全部失败）：

|尝试 | 结果 |
|---|---|
| iOS 15 / 14 / 13 三种 UA | 白屏 |
| 桌面 UA + 移动模式 | 白屏 |
| deviceScaleFactor = 3 | 白屏 |
| 同一会话重试 3 次 | 白屏 |

**结论**：属原站 uni-app runtime 层故障，非我方环境问题。

### 4.6.2 反编译方法论（已验证有效，可复用于其余 130+ 页面）

1. **取 chunk 哈希表**：从 `index.66eef648.js` 中提取 `"pages-xxx-xxx":"<hash8>"` 映射。
2. **下载页面 chunk**：`https://dadaqif.hfeyusheng.top/static/js/pages-xxx-xxx.<hash>.js`。
3. **定位 scopeId**：搜 `Object(o["a"])(i["default"], r["b"], r["c"],!1, null, "<scopeId>", ...)`，
   拿到该页面的 `scopeId`（如公告页 `215e8feb`）。
4. **切分模块**：scopeId **前一个**模块是 render 函数（template + render），另一个是 logic（data/methods/lifecycle）。
   形如 `d("828b"),Object(o["a"])(...)` 中的 `828b` 即模块 ID。
5. **提取 CSS**：CSS 在 `t.push([a.i, '...'])` 的字符串里，需 `unicode_escape` / JS 字符串解码；
   **注意 `%?N?%` 是 rpx 占位符**，解码后按 `rpx × 0.52` 换算成 px 再写入 Vue 样式。

### 4.15.3 关键交互契约

**① 按钮双事件绑定**

原站 `w-button` 同时绑定两个处理函数：

```js
t("w-button", {
  attrs: { type: "colorful", shape: "circle" },
  on:      { click: confirmConsignment },   // 组件事件
  nativeOn:{ click: openToast }            // 原生 DOM 事件
}, [ "确定寄售" ])
```

`on` 与 `nativeOn` **都会执行**——即点「确定寄售」时，既做价格上限校验并进入确认流程，
又对「未填价 / 未选账户」弹出轻提示。`w-button` 内部 `click` 方法为
`this.disabled || this.$emit('click', a)`，但本页 render **未传 `disabled`**，
因此按钮恒可点（`isDisabled` computed 在本页未被 render 引用）。

**② 低价二次确认阈值**

```js
popConfim(e) {
  if (e) {                                  // e 为事件对象，恒 truthy
    const a = 0.2 * this.low_price
    Number(this.sellingPrice) < Number(a) ? this.showPop2 = true : this.pwdPop = true
  }
}
```

阈值 = 市场最低价 × 20%。低于 → 「寄售确认」modal（`w-modal`）；
不低于 → 直接进操作密码（`pwdPop`）。

**③ 价格上限**

`Number(sellingPrice) > Number(details.product.reprice_limit)` → toast 拦截，不进弹窗。

**④ 批量寄售**

`id` 为逗号分隔的多个 `user_collection_id`：
- `getUserCollectionDetails` / `getSellConfig` 取**第一个** id
- `totalPrice = sellingPrice × 件数`，「总售价」行显示 `￥单价x件数=`
- 提交时 `sellProduct` 按 id 是否含逗号切换 `resale` / `batch_resale`

**⑤ 三层弹窗串联**

```
确定寄售
  ├─ 价格 > reprice_limit ─→ toast（终止）
  ├─ 价格 < 0.2×low_price ─→ w-modal「寄售确认」
  │      └─「继续寄售」─→ w-toast「最终确认」
  │            └─「确认」─→ password-authentification
  └─ 其他 ─────────────────→ password-authentification
                                 └─ 6 位密码满 ─→ sellProduct
                                       ├─ password_error==1 ─→ w-toast「操作密码错误，请重试」
                                       └─ 成功 ─→ /pages/order/marketDetail?id=
```

### 4.17.10 rpx 换算比例标定（重要，全站影响）

原站 H5 运行时实测 **32rpx = 16px**（比例 **0.5**），而本项目自第 1 页起统一沿用
**0.52**（32rpx = 16.64px），单处差 0.64px。**决策：保持 0.52 不变**，以免破坏已验收的 15 个页面；

若后续需要绝对 1:1，可全局把 `px = rpx × 0.52` 改为 `0.5` 并全量回归。

### 4.22.7 原站两处 bug 复刻分析（重要）

**Bug ① —— 榜单渲染出 "data1"/"my1"/"activityRule1" 三条脏数据**

根因链条：

1. 页面 script `A.list = a.data`，`a` 为 axios 响应体 → `A.list` 取到的是
   `{ data:[], my:"", activityRule:"" }` **整个对象**，而非其中的 `data` 数组；
2. 卡片组件 render 用 Vue2 `_l(A.list, function(a, e){...})`；
3. Vue2 `renderList` 对**非数组对象**取 `Object.keys(val)` 逐 key 迭代；
4. 组件把 `e`（key，字符串 `'data'`/`'my'`/`'activityRule'`）当索引用，
   `e < 3` 恒为 `false`（字符串与数字比较 → NaN），故**永远走普通序号分支**，
   并把 key 与 `+1` 拼接 → 显示 `data1` / `my1` / `activityRule1`。

**Bug ② —— 图标 404 显示为破图文字**

`04bb`（原站 env 模块）导出了 `ApiHost` / `OssUrl` / `OriginOssUrl` 等，
但**根本没有 `localBgUrl`**。于是：

- 问号图标 src = `undefined` + `"icon_question.png"` = `"undefinedicon_question.png"`
  → u-icon 再拼 `/static/icon/` + name + `.png` → 404 → 页面显示破图文字 `undefinedicon_question.png`；
- 奖牌图 src = `"undefinedranking_one.png"` 等 → 同样 404。

已用 curl 穷举原站可能路径（`/static/`、`/static/bg/`、`/static/img/`、`/static/rank/`、
`/static/icon/`、`/static/market/`、OSS 根路径等）全部 404，确认**原站从未提供这批资源**。
